# 企微本地自动化基线

本文档记录当前已验证可用的企微客户端本地收发实现，作为后续优化的回退基线。

## 稳定链路

```text
未读读取：
企微未读会话
  -> 本地脚本 /messages unreadOnly=true
  -> 菜单“选择下一个未读会话”
  -> 读取当前会话尾部最新可见消息
  -> 回传系统入站
  -> 成功 ACK
  -> Worker 每 1 秒按 currentOnly 快读看守当前业务会话
  -> 看守期间只回传新增消息，发现可执行发送任务则退出看守
  -> 空闲复位到文件传输助手

系统回复：
系统 SendScheduler
  -> realtime worker 预检任务仍有效
  -> 本地脚本 /send
  -> Cmd+F 搜索会话
  -> Enter 进入第一条搜索结果
  -> 标题校验
  -> 发送前快读尾部3条消息
  -> 校验最新消息仍匹配triggerLatestMessageId
  -> fast_path 定位输入框
  -> 写入/粘贴回复
  -> Enter 发送
  -> 回写 dispatched
  -> 空闲复位到文件传输助手
```

## 读取规则

- 实时读取只读当前会话尾部最新可见消息，默认尾部 6 行。
- 实时读取不展开整棵 AX 树，不做历史补账，不保存截图。
- 如果企微消息区是 `AXTable`，优先读取表格尾部行。
- `currentOnly=true` 只读取当前窗口，不切未读、不搜索；用于 Worker 看守当前业务会话。
- 看守循环由 Worker 控制，本地脚本每次只执行一次短读取并释放自动化锁。
- Worker 通过 `/api/wecom-client/realtime/send-scheduler/peek` 判断是否已有可执行发送任务；有任务即退出看守。
- 发送人从消息行内的头像按钮 `AXButton name/title` 读取，再和同一行的 `AXTextArea` 消息文本绑定；例如 `boom`、`JUJU@微信`、`客服助理`。
- 命中 `WECOM_AUTOMATION_MANAGED_SENDER_NAMES` 或默认 `客服助理` 时，`senderType=staff`；否则为 `customer`；没有行内发送人时才使用 `fallback_room` 低置信兜底。
- 未读轮询先检查“选择下一个未读会话”菜单项；没有未读时直接返回空批次，不读取当前窗口。
- 如果“下一个未读”跳到 `邮件提醒`、`企业微信团队`、`客户联系`、`行业资讯`、`微信客服` 或空闲会话，脚本返回 `unsupportedUnread=true`，worker 只复位，不写入系统入站。
- 当前会话快读会利用 Accessibility 元素几何信息判断消息气泡左右位置；右侧气泡按当前企微员工/托管号 `staff` 处理，避免把自回显误判成客户新消息。
- 系统入站层会再次过滤 `文件传输助手`、`邮件提醒`、`企业微信团队`、`客户联系`、`行业资讯`、`微信客服` 等非业务会话；即使本地脚本误传，也不会创建客户档案、群上下文、任务或发送队列。
- 未绑定业务群自动建档时，只复用带 `企微群待绑定` 标签的同名占位档案；不会按群名合并真实客户档案。
- 深扫只能作为人工补账或异常排查路径，不能进入实时轮询默认路径。
- 服务商历史下载继续承担完整留档、审计和最终补账确认。

## 发送规则

- 搜索框必须通过真实键盘粘贴/输入触发企微搜索刷新。
- 不允许用 AX 直接改搜索框 value 作为主路径，否则可能出现“搜索框显示新词，但结果列表仍是旧词”。
- Worker 每轮开始会先做系统调度 `peek`；如果已经存在可执行发送任务，本轮先执行 1 个发送原子动作，不让未读读取抢占已经开始的发送动作。
- 完整发送队列只在系统侧保存；本地 8791 自动化脚本不保存业务任务队列，只执行 Worker 下发的单个动作。
- Worker 常驻轻量调用 `/unread-status` 发现是否存在未读；该探测不点击未读、不切会话、不读取消息内容。
- `/unread-status` 是常驻探测，不依赖系统发送队列是否存在；探测到未读后只在 Worker 内存里标记 `unreadHint=true`。
- Worker 主循环由 `unreadHint` 触发判断：如果系统队列没有可执行发送任务，不等待系统派发“读未读任务”，直接调用 `/messages` 读取未读并回传。
- 如果系统队列已有发送任务，Worker 先完成当前 1 个发送原子动作；动作完成后如果 `unreadHint=true`，再调用 `/messages` 读未读并回传，实现 `发送1 -> 读取未读a -> 发送2/3`。
- 如果没有未读标记，发送动作完成后不做完整读取，下一轮继续调度后续发送任务；发送目标会话的新消息由 `/send` 的发送前快读保护兜底。
- 进入会话后必须校验标题包含 `expectedTitleToken`。
- `/send` 在粘贴回复前必须执行发送前快读保护，默认只读当前目标会话尾部 3 条可见消息。
- 发送前快读最新消息必须匹配系统下发的 `triggerLatestMessageId`；只有缺少 messageId 时才允许用 `triggerLatestText` 兜底，避免连续相同文本误判。
- 如果发送前发现目标会话已有新消息，`/send` 返回 `aborted_new_messages` 且不发送；Worker 先把新消息写入入站并 ACK，再取消旧任务，等待系统重新判断。
- 如果发送前无法确认目标会话最新消息，`/send` 返回 `target_latest_unverified` 且不发送。
- 输入框使用固定 AX 路径 `fast_path`，递归扫描只作为兜底。
- 本地 `/send` 必须显式传 `allowSend=true` 才会真实发送。
- SendScheduler 的队列过期从 `max(createdAt, validAfterAt/quietUntilAt)` 开始计算，避免“刚读取保护”和静默窗口把 60 秒有效期提前消耗完。
- realtime worker 输出会带 `schedulerDispatched/schedulerSkipped/schedulerExpired/preSendAborted/preSendInboundCount`，用于判断本轮到底是发送、保护跳过、过期取消还是发送前防漏读中止。

## 空闲复位

- 本地脚本新增 `/idle`，默认进入 `文件传输助手`。
- realtime worker 只在本轮实际读取、ACK、确认或发送后调用 `/idle`。
- 调用 `/idle` 前，Worker 会先做系统调度 peek；如果已经存在下一条可执行发送任务，则跳过复位，让下一轮直接执行任务。
- 多任务连续执行时不在任务之间复位，最多在本轮没有下一条可执行任务后做一次收尾复位。
- 空轮询不调用 `/idle`；如果未读检测返回的当前会话已经是 `文件传输助手`，也不会重复复位，避免持续抢占企微窗口和浪费 3 秒级耗时。
- 复位的目标可通过 `WECOM_AUTOMATION_IDLE_CONVERSATION` 修改。

## 已验证结果

- 三个会话两轮直连发送全部成功：`客户测试群`、`测试群`、`居居`。
- 发送输入框均走 `fast_path`。
- 三个会话均可读取到最新两轮测试消息。
- 系统入站生成 queued 任务后，realtime worker 可下发到本地脚本并发送成功。
- 系统下发发送后任务进入 `sent_pending_confirm`。
- 2026-06-09 未读直读测试：`/messages unreadOnly=true` 可从未读状态直接进入 `居居`，返回尾部可见消息，并读到最新消息 `测试2`。
- 2026-06-09 发送人绑定测试：`客户测试群` 可把 `boom`、`JUJU@微信`、`客服助理` 与对应消息行绑定；`客服助理` 会被标记为 `staff`。
- 2026-06-09 当前链路测试：第一轮读到 `居居` 新未读并 ACK，同会话发送被 `skipRoomIds` 保护跳过；第二轮无新未读后任务 `pwx_send_se8yjho` 通过本地企微脚本发送，状态进入 `sent_pending_confirm`。
- 2026-06-09 数据清理验证：`文件传输助手` 不再存在于客户档案或历史日志；同名 `测试群` 待绑定档案合并为 1 个，系统诊断 `ok=true`。
- 当前正式读取参数 `maxItems=5/6` 实测约 4.1-4.5 秒，瓶颈主要在 macOS Accessibility 消息行读取。

## 当前待优化点

- 未读直读在切换会话、读取消息、空闲复位都参与时仍可能超过 5 秒，需要继续压缩 Accessibility 读取耗时。
- 单聊或本机自己发送的历史消息可能没有行内头像按钮，脚本会用会话名作为 `fallback_room` 低置信兜底；生产链路必须依赖 ACK/cursor 避免重复处理旧消息。
- 直接调用本地 `/messages` 如果不传 cursor/knownMessageIds，会返回当前可见尾部消息；生产链路必须依赖系统 ACK/cursor 过滤“系统未记录的新消息”。
