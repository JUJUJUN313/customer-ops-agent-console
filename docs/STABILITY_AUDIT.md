# 稳定性审计

## 本轮重点结论

本轮重点检查了状态损坏、接口误用、重复数据、非法枚举、异常输入、闭环计划引用、任务执行时效、任务批量处理、触达草稿状态、草稿批量处理、模型连接配置、企微Webhook配置、企微会话内容存档Gateway、企微智能机器人长连接、业务会话工作台、个人微信Sidecar Gateway、个人微信单账号发送队列、SendScheduler调度、Sidecar能力声明、Sidecar出站回调、API Key/企微密钥脱敏和本地静态访问边界等隐性问题。当前系统已经比上一版更稳定：关键写入入口有边界校验，系统自检能发现更多脏数据，Agent对畸形输入更抗错，重复报价不会造成报价列表膨胀，任务能按SLA识别超时并升级，任务和草稿都支持真实批量状态写入，企微发送必须经过已确认草稿和Webhook接口，企微会话存档与长连接消息都进入受控 API 队列，Gateway成功入站后会调用 `/ack` 避免重复拉取，非文本消息不会被丢弃而是占位入站并生成客服任务，电销/销售/VIP会话工作台按业务范围过滤且默认只展示真实来源，回复按风险进入队列或人工确认、不伪装已发送，个人微信Sidecar未声明 `canReceive=true` 时不拉取消息、未声明 `canSend=true` 时任务保持待发送，个人微信链路按 `roomId` 去重、合并同群连续客户消息、同群FIFO、账号并发、分钟上限、过期重判、人工放行、Sidecar发送回调、自回显确认和失败退避调度，模型配置会校验URL和模型名，本地状态文件不会被静态路径直接读取，前端状态接口不会返回明文API Key、企微Webhook、Bot ID、Secret、会话存档Secret或RSA私钥。

## 已发现并修复的隐性问题

| 问题 | 风险 | 修复 |
| --- | --- | --- |
| `/api/agents/orchestrator/run` 仍要求存在当前客户 | 当前选中客户失效时，闭环编排Agent无法运行 | `runAgentAction` 对 `orchestrator` 免客户依赖 |
| 客户阶段可写入任意字符串 | 状态机失效，客户旅程无法正确分组 | 新增阶段枚举校验 |
| 任务状态可写入任意字符串 | 任务中心统计和按钮状态失真 | 新增任务状态枚举校验 |
| 客户风险和任务优先级可被异常值污染 | 自检报警、任务排序和风控展示失真 | 新增风险与优先级枚举校验 |
| 销售结果可写入未知值 | 结果事件存在但客户阶段不变，形成假闭环 | 新增销售结果枚举校验 |
| 同品牌型号配置报价重复新增 | 报价页出现重复卡片，推荐结果不稳定 | 按品牌+型号+配置更新已有报价 |
| 畸形数值可能导致评分为 `NaN` | 外呼评分和客户意向分异常 | Agent评分、销售承接和客户档案更新使用安全数值转换 |
| 脏客户缺少标签或关注型号数组 | 销售结果、报价订阅写入时可能崩溃 | 写入前自动补齐 `tags` 和 `watchedModels` |
| 报价型号不是字符串 | 消息解析可能因类型假设中断 | 已将报价型号归一为字符串后参与识别 |
| 非字符串消息可能导致意图识别崩溃 | API或测试传入异常消息时Agent报错 | 消息识别统一转字符串 |
| 销售样本缺少话术或质检分异常 | 销售学习结果失真，Agent引用低质量脏样本 | 新增销售样本输入校验和自检项 |
| 渠道消息不沉淀上下文 | VIP群分流只能看单条消息，无法判断重复问题和未结任务 | 新增离线会话窗口和渠道入站会话写入 |
| 会话引用或消息为空 | Agent上下文失真，自检无法发现坏会话 | 新增会话引用和消息可用性自检 |
| 任务缺少时效字段 | 任务可生成但无法判断是否超时、是否需要主管介入 | 自动补齐 `createdAt`、`dueAt`，新增SLA报表和超时升级动作 |
| 自检先补齐SLA时间再检查 | 坏SLA时间会被自愈逻辑掩盖，诊断漏报 | 自检改为先记录原始坏时间，再执行任务时间补齐 |
| 负责人角色和消息发送角色未校验 | 任务分派和VIP上下文可能出现未知角色，后续排班/分流失真 | 新增负责人角色和发送角色枚举校验 |
| 状态集合被手工删掉 | `tasks`、`events`、`auditLog` 等数组缺失会导致写入动作崩溃 | `cloneState` 统一补齐集合字段为空数组 |
| `data/state.json` 可被静态路径读取 | 绕过受控API直接暴露本地状态文件 | 静态服务禁止访问 `data/` 目录和隐藏文件 |
| Agent模型来源不可追踪 | 后续接入真实LLM后无法判断某次运行使用了哪个模型 | 新增全局/Agent模型连接配置，运行结果写入生效API URL、模型和来源 |
| 模型配置容易被误解为真实模型调用 | 用户可能以为Agent默认都会调用外部LLM，形成假能力 | 新增 `AgentRun.execution`，明确默认本地规则引擎；只有测试连接或勾选真实LLM增强时才会调用模型 |
| 模型配置不够接近真实接入 | 只有供应商和模型名无法支撑后续真实LLM/语音执行器 | 增加API URL、API Key、ASR、TTS、Agent独立覆盖和URL校验 |
| API Key展示和报告泄露风险 | 模型配置报告或运行记录可能暴露明文Key | `/api/model-config` 和 `AgentRun.modelConfig` 只返回Key是否已配置/掩码，不返回明文Key |
| `/api/state` 返回明文API Key | 前端加载状态时可能把本地密钥暴露在页面状态和浏览器内存中 | 服务端返回 `publicState`，模型配置只包含空 `apiKey`、`apiKeyConfigured` 和 `apiKeyMasked` |
| `/api/state` 可能返回企微Webhook | 测试群机器人Webhook等同发送密钥，泄露后可被外部滥发 | `publicState` 和 `/api/wecom/config` 只返回空 `webhookUrl`、是否已配置和掩码 |
| 企微已发送状态可能被普通状态接口伪造 | 草稿未真实发送却被标成已触达，形成假闭环和错误客户事件 | 普通状态更新拒绝 `企微已发送`；只有 `/api/outbound-drafts/:draftId/send-wecom` 成功后才写入 `wecomDelivery` 和外部副作用 |
| 未确认草稿可能被直接发送 | 未复核文案可能进入企微测试群，带来误触达和合规风险 | 企微草稿发送接口只允许 `已确认` 草稿；高风险批量确认仍受前端阻断 |
| 企微Webhook失败不留痕 | 配置错误或Webhook返回失败时，用户无法判断是否真的发出 | 发送测试和草稿发送都会写入 `wecomLogs`，记录成功/失败、错误、耗时和是否触发外部发送 |
| 企微智能机器人凭据泄露风险 | Bot ID/Secret 泄露后可能被外部连接机器人 | `/api/state` 和 `/api/wecom/config` 只返回掩码；保存时空字段保留旧值，显式清空才删除 |
| 企微多个群消息可能混档 | 每个VIP小群对应不同客户，如果只用默认客户会串档 | 长连接入站按 `chatid` 查找 `WeComBinding`；未知群自动生成待绑定档案，人工绑定真实客户前不视为已绑定 |
| 企微重复推送会重复建任务 | WebSocket 重连或重放可能导致同一消息多次进入系统 | `/api/wecom/inbound` 按 `externalMessageId/msgid` 去重，重复消息只写去重日志，不再跑Agent |
| 企微机器人出站回写可能重复展示 | bridge 同一回复回写多次会让会话工作台出现重复机器人消息 | 出站回写也按 `externalMessageId` 幂等处理，重复只写 `重复出站` 日志 |
| bridge直接写JSON会绕过队列 | 长连接进程和前端同时写文件可能互相覆盖 | bridge 只调用本地 `/api/wecom/inbound` 和 `/api/wecom/aibot/status`，由 `mutationQueue` 串行写状态 |
| 会话内容存档重复入站 | 存档游标回放或Gateway重试可能重复生成群上下文和队列 | `/api/wecom/archive/inbound` 将存档消息转成统一入站结构，按 `messageId` 去重，重复消息只写日志 |
| 会话存档成功入站但Sidecar不确认 | 主系统处理成功后如果不ACK，Sidecar下轮可能重复推同一批消息 | `scripts/wecom-archive-gateway.mjs` 成功入站后调用Sidecar `/ack`，回写 `cursor/seq/messageIds`，ACK失败会写入 `ACK失败` 并中断本轮 |
| 会话存档非文本消息被跳过 | 图片、文件、语音通常没有文本正文，真实拉取时可能被脚本丢弃，客服看不到客户发了附件 | Gateway和入站接口会把非文本消息转为 `[image消息]` 等占位文本，并生成客服人工查看任务 |
| 会话存档Gateway状态不可见 | Sidecar失败、解密失败或游标异常时，页面可能误以为仍在正常读取 | 新增 `/api/wecom/archive/status` 和 `npm run wecom:archive` 状态回写，记录连接、拉取、解密、错误、游标和最近消息时间 |
| 会话存档Sidecar是否启动不可见 | 配置填完但Sidecar没开时，业务侧只能从脚本失败里猜问题 | 新增 `/api/wecom/archive/check-sidecar` 和接入总控检查按钮，配置缺失或 `/health` 不可达会回写状态和日志 |
| 会话工作台可能混档 | 企微、个人微信、本地调试会话如果按客户名简单合并，会把不同外部群串到同一客户 | `ChatSession` 按 `roomId/chatId/sessionId` 投影，未知外部群必须先绑定客户，绑定前保持待绑定状态 |
| 会话工作台业务混杂 | 电销、销售和VIP人员如果进入同一全量会话列表，容易处理到非本部门群或误判客户阶段 | 导航拆成“电销会话”“销售会话”“VIP会话”，同一会话能力按渠道、客户阶段和会员状态过滤展示 |
| 会话工作台回复形成假发送 | 业务人员在聊天页输入回复后，界面如果显示已发送会误导真实触达结果 | 外部群低风险回复只进入SendScheduler，高风险进入人工确认；本地会话只生成草稿，真实回读确认前不算完成闭环 |
| 客户池入口被表单挤占 | 业务人员进入客户池时先看到新增/维护表单，会遮挡核心客户列表 | 客户池改为列表优先，新增档案和客户维护都进入二级页面，右上角新增，双击客户行进入详情 |
| 客户池双击被单击重渲染打断 | 双击客户行时第一次点击触发整页渲染，会导致第二次点击找不到原行 | 客户列表单击只更新选中高亮不整页重渲染，双击再进入详情维护 |
| 业务客户范围被重置筛选清掉 | 销售/VIP客户页重置筛选后可能回到全量客户 | 重置筛选会保留当前业务阶段范围，销售/VIP只看自己的客户阶段 |
| 个人微信同账号被误做无限并行发送 | 单个个人微信账号无法承受多Agent无限并行发送，容易乱序、限频或风控 | `personalWechat` 只允许一个 AccountAgent；SendScheduler按账号 `concurrency`、分钟上限和最小间隔受控调度 |
| 个人微信同群待发堆叠 | 客户连续发多条消息时，旧回复可能过期或刷屏 | 同一 `roomId` 只保留一个活跃任务，新客户消息会合并到活跃任务；员工或托管号回复会取消同群待发 |
| 个人微信重复入站重复回复 | 客户端重连或消息回放可能重复生成自动回复 | `/api/personal-wechat/inbound` 按 `messageId` 去重，重复消息只写日志，不重复生成决策或队列 |
| 个人微信旧回复过期仍被发送 | 客户后续上下文可能已经变化，旧回复继续发出会造成误导 | SendScheduler调度前按 `maxQueueAgeSeconds` 取消过期任务，要求重新判断 |
| 个人微信调度绕过限频 | 脚本快速运行调度可能突破单账号发送节奏 | SendScheduler按 `maxSendsPerMinute`、同群FIFO和账号并发检查可发送任务，限频中保持待发送并写日志 |
| 高风险个人微信任务被误确认 | 人工确认队列如果能直接回读确认，会绕过销售/客服复核 | 新增 `approve` 放行动作；`confirm` 只接受 `sending/sent/sent_pending_confirm`，不能直接确认 `manual_required/queued` |
| 个人微信提交发送被误当成完成 | 外部Gateway提交发送成功不代表群里已出现消息，可能形成假闭环 | 新增 `sent_pending_confirm` 状态；只有自回显或会话存档回读后才进入 `confirmed` 并写客户事件 |
| Sidecar缺配置仍调度发送 | 未配置真实出站地址时任务可能显示发送中但实际无人处理 | Sidecar模式缺 `sidecarUrl` 时不调度，写入 `Gateway未配置` 日志 |
| Sidecar可达但没有收发能力仍被使用 | `/health` 只表示服务在线，不等于具备真实接收或发送权限，若继续调度会形成假接入 | `/api/personal-wechat/gateway/check` 读取 `canReceive/canSend/sendMode/supportsAck/supportsConfirm/supportsRecall/loginStatus`；SendScheduler要求 `canSend=true`，否则任务保持 `queued` 并写明“出站Sidecar未声明可发送能力” |
| Sidecar发送结果不可追踪 | 外部发送服务成功/失败后如果不回写，主系统无法审计 | 新增 `dispatched` 回调、`gatewayRequestId/externalMessageId`、Gateway状态和出站脚本 `personal-wechat:gateway` |
| 个微Gateway健康状态不可见 | Sidecar未启动、URL填错、仍在Mock模式或未登录时，销售容易误判是否能真实读取/发送 | `/api/personal-wechat/gateway/check` 和接入总控检查按钮会读取 `canReceive/canSend/supportsAck/loginStatus`，Mock/Sidecar/停用三种模式都会写入明确状态 |
| 个人微信发送失败不留痕 | 真实Gateway失败后如果没有状态记录，销售无法判断是否接管 | 新增发送失败动作，任务进入 `failed`，记录 `attempts/retryAfterAt/error` 和人工接管日志 |
| 保存模型配置时空Key会误清除旧Key | 用户只改模型名或温度时可能把可用密钥清空，导致模型测试和LLM增强突然失效 | 空Key默认保留旧密钥；新增 `clearApiKey` 和前端“清空已保存Key”显式操作 |
| 模型配置无法验证 | 用户填了API URL和Key也不知道是否可用，容易形成不可用配置 | 新增 `/api/model-config/test`，缺Key不发请求，配置完整时真实调用OpenAI兼容 `chat/completions` |
| 外部模型失败可能破坏主流程 | 网络超时、模型报错或Key错误可能导致Agent无法落库 | LLM增强在本地规则Agent落库后按需执行；失败只写入 `llmEnhancement` 错误和审计，本地结果、任务和草稿仍保留 |
| 模型温度字段不易理解 | 销售或运营不知道温度会影响稳定性还是创造性，容易误配 | 前端把温度标注为“创造性”，说明低温更稳定保守、高温更发散，并给出建议区间 |
| 客户池样例过少 | 搜索、筛选、分阶段运营和批量Agent缺少足够测试数据 | 初始客户池扩充到18个，覆盖多阶段、负责人、会员状态和关注型号 |
| Agent生成文案容易被误解为已发送 | 销售或电销可能以为系统已短信/企微触达客户，形成假闭环 | 新增 `OutboundDraft` 本地草稿队列；未发送草稿 `externalSideEffects=false`，企微已发送草稿必须带 `wecomDelivery` |
| 忙碌状态结束会覆盖业务禁用按钮 | 已确认草稿、已订阅报价等按钮可能被重新启用，造成重复操作入口 | `setBusy(null)` 改为重渲染页面，恢复由业务状态决定的 `disabled` |
| 业务页面暴露内部JSON | 销售侧看到原始Agent对象会误以为需要理解代码，且容易把内部字段当作业务结论 | 总览、Agent控制台、销售学习、本地消息和审计日志统一改为业务摘要/卡片展示；新审计写入业务摘要 |
| 系统蓝图依赖旧静态图片 | 总览无法准确表达当前系统模块协作和数据回流，维护时容易过期 | 改为页面内结构化蓝图，展示客户流转链路和共享系统底座 |
| Agent输出可能串客户 | 切换客户后仍展示最近一次其他客户的Agent结果，销售可能误用话术或任务判断 | `AgentRun` 写入 `customerId/customerName`，Agent控制台只展示当前客户对应的最新建议 |
| VIP上下文可能串客户 | 会话工作台切换客户后仍显示其他客户最近的VIP分流上下文 | 会话工作台按当前客户过滤 `VIP群分流Agent` 结果 |
| 界面在窄屏挤压 | 蓝图、模型配置表单、表格和导航在中小屏容易挤压或过长 | 蓝图改三列/响应式，模型卡片内部两列，移动端导航改为业务分组折叠菜单，表格增加边界和稳定表头 |
| 左侧导航页面过多 | 销售侧需要在过长菜单中寻找页面，容易进错流程或误解系统结构 | 改为一级业务模块和二级菜单：总览、客户管理、电销管理、销售管理、VIP群管理、设置；系统接入入口归设置 |
| 自检覆盖不够 | 重复客户、非法阶段、非法任务状态等脏数据不被发现 | `diagnoseState` 扩展到重复ID、阶段、意向分、任务状态、优先级、负责人角色、SLA时间、事件内容、闭环计划引用 |
| 任务中心只能单条处理 | 销售或运营需要逐条点任务，批量跟进/关闭容易漏处理且无统一审计 | 新增 `/api/tasks/batch-status` 和前端批量工具条，批量动作逐条写事件并汇总审计 |
| 草稿队列只能单条处理 | 大量Agent草稿需要逐条确认/废弃，队列积压且处理记录分散 | 新增 `/api/outbound-drafts/batch-status` 和前端批量工具条，批量动作逐条写状态时间、事件和审计 |
| 高风险文案可能被批量确认 | 投诉、赔偿、退款、锁价等敏感草稿如果批量放行，会形成合规风险 | 前端草稿风险识别标记高风险，并阻止高风险草稿批量确认 |
| 报价查询筛选不足 | 只按品牌筛选时，用户仍难以从结构化报价中快速找到型号、配置和价格范围 | 报价页新增型号搜索、配置、库存、最低价和最高价筛选 |
| 总览缺少角色承接视角 | 电销和销售无法从总览直接看到自己该处理的客户和任务 | 总览新增电销/销售工作台，并可跳转到客户或任务筛选页 |

## 当前稳定性保障

- API 写入通过 `mutationQueue` 串行执行，降低并发写 `data/state.json` 的覆盖风险。
- 所有关键写入会返回完整状态，前端以服务端状态重新渲染。
- 客户、任务、报价、模板、销售结果、客户风险、任务优先级、负责人角色、销售样本、渠道消息均有边界校验。
- 系统自检可发现状态引用错误、重复ID、非法阶段、非法任务状态、非法任务时间、非法负责人角色、异常事件、非法报价和高风险模板放行。
- 静态服务禁止直接访问 `data/` 和隐藏文件，状态读取统一走 API。
- `/api/state` 返回前端公开状态，模型 API Key、企微Webhook、Bot ID 和 Secret 明文不会进入页面；`/api/model-config`、`/api/wecom/config` 也只返回掩码和配置状态。
- 模型配置会校验全局LLM API URL和模型名，Agent覆盖为空时明确继承全局；Agent运行结果同时保留模型连接和执行边界。
- 模型配置保存时空Key默认保留旧Key，只有显式 `clearApiKey` 或前端勾选清空项才会清除密钥。
- 模型连接测试和Agent真实LLM增强使用OpenAI兼容 `chat/completions`，不会把API Key返回前端或写入审计明文。
- 真实LLM增强只生成本地建议和草稿，`externalSideEffects` 仍为 `false`，不会自动外呼、发短信、发企微私聊或写CRM。
- 企微测试群发送必须先配置Webhook、启用路由并确认草稿；成功后才会把草稿标记为 `企微已发送`。
- 企微智能机器人长连接必须先保存 Bot ID/Secret 并启动 bridge；bridge 认证、断开和错误状态会写入 `wecomLogs` 和 `aibot.bridgeStatus`。
- 企微入站按 `externalMessageId/msgid/messageId` 去重，按 `chatid/roomId` 独立归档；未知群进入待绑定档案，避免不同客户群消息串档。
- 企微会话内容存档Gateway会通过 `/api/wecom/archive/status` 回写连接、拉取、解密、ACK、错误、游标和最近消息时间；标准入站会复用AccountAgent群上下文、去重、风控和发送队列。
- 企微接入页提供真实连接中心，能直接看到会话存档、智能机器人、测试群发送和个人微信Sidecar四条链路的配置缺口与运行状态；本地模拟入站不再作为业务界面入口。
- 会话存档Sidecar检查只访问 `/health`，不携带企微会话存档Secret或RSA私钥。
- 电销、销售、VIP会话工作台从已有状态投影会话，不另起孤立数据库；绑定客户、回复入队、人工确认、草稿生成都会回写客户档案、事件、任务、队列和审计。
- 会话工作台外部群回复必须经过风险判断，高风险内容不会自动进入发送调度；无真实出站通道时不会显示真实已发送。
- 个人微信 AccountAgent 入站按 `messageId` 去重，按 `roomId` 隔离群上下文；低风险自动排队，高风险人工确认，连续客户消息合并，员工/托管号回复取消同群待发。
- 个人微信 SendScheduler 会执行队列过期重判、同群FIFO、账号并发、分钟上限、Gateway模式检查、`canSend`能力门禁和失败退避，避免旧回复继续发送、同账号快速连发、无能力Sidecar伪发送或同群乱序。
- 个人微信高风险任务必须人工放行后才会回到待发送队列，不能直接确认。
- 个人微信发送链路区分 `sending`、`sent_pending_confirm` 和 `confirmed`；已提交发送不等于闭环完成，只有回读确认后才会写入客户事件。
- `npm run personal-wechat:gateway` 只处理 Sidecar模式下的 `sending` 任务，成功后回写 `dispatched`，失败后回写 `fail`。
- 个人微信Gateway健康检查不拉取也不发送客户消息，只检查模式、Sidecar URL、`/health` 可达性和 `canReceive/canSend/sendMode/supportsAck/supportsConfirm/supportsRecall/loginStatus` 能力声明。
- 模型配置支持ASR/TTS语音模型参数，系统自检会提示语音模型配置状态。
- 前端模型配置页解释温度含义，降低误配风险；业务页面展示模型调用边界时不展示API Key明文。
- 客户池和客户列表搜索筛选只影响前端展示，不写入客户档案，避免筛选操作污染业务状态；业务入口的阶段范围由客户作用域保留，重置筛选不会越权展示其他阶段客户。
- 系统自检会检查Agent运行记录是否标明本地执行/外部副作用状态，避免“已运行但不可追踪”的假闭环。
- 触达草稿会校验客户、渠道、状态和正文，确认、复制、人工已处理和废弃都只写入本地事件与审计，不会发出外部消息。
- 任务批量状态更新会校验任务ID和合法状态，逐条写入任务事件，批量完成会写入 `completedAt`。
- 触达草稿批量状态更新会校验草稿ID和合法状态，逐条写入状态时间、客户事件和审计，不能批量伪造企微已发送。
- 前端草稿风险识别会阻止高风险文案批量确认，降低敏感话术误操作风险。
- Agent控制台把运行结果转为判断、建议动作、话术草稿、报价推荐和后续事项，避免业务用户直接接触内部JSON结构。
- Agent控制台按当前客户过滤运行结果，避免销售在切换客户后看到其他客户的建议。
- 会话工作台按当前客户过滤VIP分流上下文，避免群问题摘要串到其他客户。
- 顶部操作区、Agent建议区、表格和移动端导航均增加布局保护，减少滚动、挤压和误点。
- 前端忙碌态结束后会重新按当前状态渲染按钮，避免异步操作完成时把业务禁用按钮误放开。
- 前端有空数据、加载失败、处理中和防重复提交保护。
- 测试覆盖正常流程、异常输入、闭环编排、能力审计和稳定性边界。

## 仍需关注的生产风险

- 本地 JSON 文件不是生产级数据库，没有事务、锁粒度、备份、迁移和并发审计。
- 当前 ID 仍为随机短ID，生产环境应由数据库或ID服务生成。
- 当前API Key会存入本地 `data/state.json`，生产环境应迁移到密钥管理服务、环境变量或后端加密存储。
- 任务已有SLA超时升级，但还没有负责人排班、真实提醒推送、关闭质检和重试机制。
- 高风险模板目前允许被手动启用，但自检会报警；生产环境应增加审批流。
- Agent默认仍是本地规则系统；真实LLM增强已可按需调用，但还没有内容安全护栏、知识库版本控制、成本统计、调用日志和人工审批策略。
- 企微会话内容存档当前固定了Gateway、`/health`、`/pull`、`/ack` 和标准化入站契约，真实拉取、消息解密、客户同意校验、客户联系加好友回调、企业通讯录、成员私聊全量同步、图片/文件下载入库、撤回/引用回复、权限审批、短信、外呼、交易系统接入后，还需要更完整的签名校验、重放保护、幂等键、失败重试和合规审计。
- 会话工作台当前主要覆盖文本会话和队列闭环，图片、文件、引用、撤回、已读、群成员变更和多员工协作状态仍需生产化补齐。
- 个人微信Sidecar 当前具备主系统接收/ACK/发送/确认契约，不具备生产级登录态保护、真实协议适配、设备风控、限频退避、掉线重连、二维码托管、账号封禁兜底和完整审批流。
